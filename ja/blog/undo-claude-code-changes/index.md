# Claude Code の変更を元に戻す方法 — 閉じたセッションのターンも復元

> AI エージェントが 3 ターン前に何かを壊した? git、Claude Code の /rewind、そして gtree の「AI の各ターン」の 3 つの取り消し方を比較します。gtree ならどのターンのファイルも復元でき、新しいセッションは前回の続きを覚えています。

Published: 2026-10-22 · DobbyLab · https://gtree.dobbylab.com/ja/blog/undo-claude-code-changes/

Claude Code が加えた変更を元に戻す方法は 3 つあります。**git** は未コミットの編集を破棄できます(`git restore <ファイル>`)が、戻れるのは直前のコミットまでです。**Claude Code 内蔵の巻き戻し**(`/rewind`)は会話の途中の時点までコードを戻せますが、対象はファイル編集ツールで行った変更だけです。**gtree** はエージェントがターンを終えるたびに worktree のチェックポイントを保存するので、どのターンが何を変えたかを確認し、2 回のクリックでそのファイルを元に戻せます。どのセッションのターンでも、先週閉じたセッションのものでもかまいません。さらに新しいセッションは、前回どこまで進んだかを知った状態で始まります。

## AI の変更を戻すのは、なぜ自分の変更より難しいのか

自分でコードを書くとき、コミットはおおむね考えの流れに沿っています。AI のセッションはそうではありません。20 分の間にエージェントが 8 ターン進め、15 ファイルを触り、十数個のコマンドを実行する。それがすべて、あなたの 2 つのコミットの間で起きます。そして 6 ターン目でテストが壊れます。6 ターン目の変更だけを取り消して、1〜5 ターン目の成果は残したいところです。

git だけではこれを表現できません。git から見れば、直前のコミットから今までの間には何も起きていないからです。

## git で Claude Code の変更を元に戻すには?

AI が作業を始めてから一度もコミットしていなければ、すべて捨てるには git がいちばん手早い方法です。

```bash
git status                     # 何が変わったか
git diff                       # どう変わったか

git restore src/auth.ts        # 追跡中の 1 ファイルの変更を破棄
git restore .                  # 追跡中の全ファイルの変更を破棄

git clean -n                   # 削除される未追跡ファイルを事前に確認
git clean -fd                  # 実際に削除(元に戻せないので注意)
```

AI にタスクを渡す前に逃げ道を用意するなら、先に退避しておきます。

```bash
git stash push -u -m "AI に渡す前"   # 新規ファイルも含めて手元の変更を退避
git stash apply                       # あとで戻す(stash は残る)
```

あるいはプロンプトを送る前に毎回コミットする方法もあります。機能はしますが、履歴が「wip」コミットで埋まって後で squash が必要になりますし、忘れるのはたいてい一番困るときです。

## Claude Code の /rewind はどう動く?

Claude Code は会話の途中で独自にチェックポイントを保存しています。`/rewind`(または入力欄が空の状態で Esc を 2 回)で以前のメッセージを選ぶと、会話・コード・その両方をその時点に戻せます。「直前の 2 ターンは方向が違った」というときには、最も手早い手段です。

チェックポイントは会話と一緒に保存されるので、`claude --resume` で過去の会話に戻っても `/rewind` を使えます。セッションごとに直近 100 個のチェックポイントが保持され、既定では約 30 日で削除されます。

Claude Code のドキュメントによると、次の変更は記録されません。

- **シェルコマンドで変更したファイル**:`rm`、`mv`、`cp`、`sed` の一行、フォーマッタ、コード生成ツールなど
- **サブエージェントによる編集**(通常は記録されません)
- **セッション外での変更**:手作業の編集や、同時に動いている別のセッションによる変更

手軽なローカルの取り消し手段であって、バージョン管理の代わりではない、という位置づけです。

## gtree ならどのターンにもロールバックできる

[gtree](https://gtree.dobbylab.com/ja/) は別のアプローチを取ります。個々の編集を追跡するのではなく、結果をスナップショットします。Claude Code と Codex に対応しています。

### ターンが終わるたびにチェックポイント

Claude Code(または Codex)に接続すると、エージェントがターンを終えるたびに、gtree は worktree の状態を**チェックポイント**として保存します。編集操作ではなくファイルそのものを記録するので、シェルコマンドによる変更や新しく作られたファイルも含まれます。git で無視されている新規ファイルや 1 MB を超える新規ファイルは対象外です。

チェックポイントはリポジトリ内の通常の git オブジェクトとして、専用の参照の下に保存されます。どのブランチにも属さず、保存の際にブランチ、ステージングエリア、ファイルに触れることはありません。保存期間は 30 日です。

### 各ターンの変更を確認:「変更 › AI の各ターン」

右パネルの**「変更」**タブ(⌃⇧G)を開きます。上半分は未コミットのファイル、下半分が**「AI の各ターン」**で、現在の worktree のすべてのターンが並びます。各ターンは 2 行で、1 行目にプロンプトと時刻、2 行目に変更したファイル数とファイル名(「3 ファイル · session.ts など」)が出ます。ほとんどのターンは質問と回答だけなので、標準ではファイルを変更したターンだけを表示します。「⋯」メニューから残りも表示できます。

ターンをクリックすると、中央に詳細が開きます。

- あなたのプロンプトと、エージェントの最後の返答(最初の 4 行。「すべて表示」で全文)
- そのすぐ下に、そのターンで何が変わったかの差分

セッションをまたいで使えます。昨日閉じた会話のターンも一覧に残っているので、「昨夜 AI は何を変えたのか」に答えられます。

### 「このターンに復元」で何が起きるか

ターンを選んで**「このターンに復元」**をクリックします。ボタンが赤くなり**「もう一度クリックで復元」**に変わるので、うっかりクリックで何かを上書きすることはありません。

2 回目のクリックで、**そのターンで変更されたファイル**が、ターン終了時の状態にそのまま書き戻されます。その時点で存在しなかったファイルは削除されます。完了すると「このターンの 2 ファイルを終了時の状態に戻しました」のように表示されます。

触れるのはそのターンで変更されたファイルだけです。作業フォルダ全体をその時点まで巻き戻すわけではなく、ブランチやステージングエリアもそのままです。

### 問題のターンを取り消すには

先ほどの例で、6 ターン目がテストを壊したとします。

1. **まず 6 ターン目を選び**、変更されたファイルを確認します。これが戻すべきファイルの一覧です。
2. **それより前で、同じファイルを最後に変更したターンを探し**(たとえば 4 ターン目)、選んで「このターンに復元」を 2 回クリックします。これらのファイルは 4 ターン目の終了時、つまり 6 ターン目が始まる前の状態に戻ります。
3. **4 ターン目がほかに何を変更したかも確認します。** 復元では 4 ターン目が触れたファイルがすべて書き戻されるため、そのうちのどれかを 5 ターン目でも変更していた場合、5 ターン目の変更も一緒に元に戻ります。クリックする前に確認してください。
4. **それより前のどのターンも変更していないファイル**は、まず `git diff <ファイル>` で確認し、6 ターン目の変更だけなら `git restore <ファイル>` で戻します。6 ターン目で新しく作られたファイルは削除します。

それ以外はそのままです。ほかのファイル、ステージングエリア、ブランチ、コミットには触れません。復元自体は作業フォルダへの通常の変更なので、上の未コミットの変更で確認することも、そのままコミットすることもできます。

### コミットグラフで AI のターンを見る

**「コミット履歴」**(⌘3)では、ツールバーの**「AI の各ターン」**スイッチをオンにすると、直近 3 日間のチェックポイントが現在のコミットから伸びる追加のコミットとして描かれ、そのターンのプロンプトがタイトルになります。クリックすれば、通常のコミットと同じように変更内容を確認できます。

### 変更の背景にある会話を探す

取り消す前に、*なぜ*その変更がされたのかを知りたいこともあります。AI ページで **⌘Y** を押すと、上部に小さな「履歴」ウィンドウが降りてきて、リポジトリのすべての worktree の過去の会話が「今日」「昨日」「過去 7 日間」「それ以前」に分かれて並びます。入力するだけで全体を検索できます。Claude Code の会話なら **↩** でその worktree で会話を続け、**⌘↩** で一致箇所がハイライトされた読み取り専用のリプレイを開きます。続けたくなったら、そこにある「このセッションを続ける」から再開できます。(Codex のターンも「AI の各ターン」に並び、復元できます。ここから過去の会話を続けられるのは、現時点では Claude Code のセッションです。)

### 新しいセッションは前回の続きを覚えている?

取り消しで解決できるのは「元に戻したい」まで。もう半分の「前回どこまでやったっけ?」に応えるのがこの仕組みです。worktree で新しいセッションを始めると、エージェントはそこでの前のセッションの短い要約を自動的に受け取ります。いつ終わったか、最近のプロンプト、最後に何を言ったか、どのファイルに触れたか。だから一から手探りするのではなく、前回止まったところから続けられ、何をすでに試したかもわかっています。

エージェントは自分でさらに遡ることもできます。gtree の `recall` ツールは、すべてのプロジェクトにわたって直近 30 日間のターンのプロンプトと結論を検索するので、「先週トークンの更新はどう直したんだっけ?」にもエージェント自身が答えを見つけられます。

## git・/rewind・gtree、どれを使う?

| | git | Claude Code `/rewind` | gtree |
|---|---|---|---|
| 取り消しの単位 | コミット / ファイル全体 | 会話内のメッセージ | 完了したターン |
| シェルコマンドによる変更 | 可(未コミット分) | 追跡しない | 可 |
| 過去のセッション | コミットしていれば | その会話を再開すれば可(約 30 日) | 全セッション、30 日間、再開不要 |
| 新しいセッションが前回の内容を知っている | いいえ | いいえ | はい |
| 各ステップの変更内容 | コミット間のみ | 会話の中で | ターンごとの diff |
| ブランチ / ステージングへの影響 | `reset` や `stash` はあり | なし | なし |

3 つは組み合わせて使えます。会話中の「いや、そうじゃない」には `/rewind`、シェルコマンドによる変更や、後になって気づいてどのセッションの変更か思い出せないときは gtree、コミット済みのものは git、という使い分けです。

## 取り消しを楽にする習慣

1. **タスクが動いたらコミットする。** 毎ターンコミットする必要はありません。ターンごとのチェックポイントがあれば、保険としての「wip」コミットは不要です。
2. **1 タスク 1 worktree。** あるタスクのターンを戻しても、別タスクのファイルには影響しません。[git worktree で Claude Code を複数並列で動かす方法](/ja/blog/run-multiple-claude-code-git-worktree/)も参考にしてください。
3. **復元の前に diff を見る。** そのターンの diff が、復元で書き換わるファイルの一覧です。
4. **2 つのセッションに無自覚に 1 つのフォルダを共有させない。** 一方のターンを戻すと、もう一方の作業に影響することがあります。[2 つの AI エージェントが同じファイルを編集するとき](/ja/blog/ai-agents-editing-same-file/)もご覧ください。

## よくある質問

### セッションを閉じた後でも Claude Code の変更を戻せますか?

戻せます。Claude Code 自体なら、`claude --resume` でその会話に戻れば `/rewind` が使えますが、対象はファイル編集ツールによる変更だけです。gtree なら、直近 30 日間のターンはどのセッションのものでも「AI の各ターン」に残り、シェルコマンドで変更したファイルも含まれます。git の場合は、変更がまだ未コミットか、変更前にコミットしていた場合に限られます。

### 復元したのに、問題のターンで変わったファイルが戻りません。なぜですか?

復元で書き戻されるのは、**そのターン**で変更されたファイルです。5 ターン目を取り消すために 4 ターン目へ復元すると、書き戻されるのは 4 ターン目で変更されたファイルです。5 ターン目で変更されていても、4 ターン目が触れていないファイルはそのまま残ります。5 ターン目を開いて対象ファイルを確認し、git で戻すか、それらを変更していたもっと前のターンから復元してください。

### 復元するとコミットやブランチは変わりますか?

変わりません。書き換えるのは作業フォルダ内のファイルだけで、コミット、ブランチ、ステージングエリアはそのままです。結果をコミットするかどうかはあなたが決めます。

### Codex でも使えますか?

使えます。Codex のセッションでもターンごとに同じようにチェックポイントが保存されるので、そのターンも「AI の各ターン」に並び、同じ方法で復元できます。⌘Y から過去の会話を続けられるのは、現時点では Claude Code のセッションです。

### 新しいセッションは前のセッションの内容を知っていますか?

gtree を使えば知っています。worktree で新しいセッションを始めると、そこでの前のセッションの要約(最近のプロンプト、最後の返答、触れたファイル)を自動で受け取ります。それより前のことは、エージェントが `recall` ツールで検索できます。

### チェックポイントには自分で編集した内容も含まれますか?

含まれます。チェックポイントはターン終了時の作業フォルダ全体を記録するため、前のターン以降に手で編集した内容も入ります。

gtree のローカル機能は無料で、登録も不要です。gtree があなたのコードをアップロードすることはありません。[gtree をダウンロード](https://gtree.dobbylab.com/ja/)して Claude Code か Codex に接続すれば、次にターンが失敗しても、何が変わったかを確かめて、そのファイルを元に戻せます。
