エージェントを並行で動かすあなたへ · Claude Code と Codex に対応

エージェントを 5 つ同時に。 どれがあなた待ちか、 ひと目で。

gtree は、AI コーディングエージェントをいくつも同時に動かす人のためのネイティブなデスクトップアプリです。エージェント同士はお互いの作業が見えていて、同じ worktree のエージェントが同じファイルを編集するときは、どちらが先か自分たちで決めます。あなたが呼ばれるのは、本当に必要なときだけです。

01お互いが見える

同じファイルを編集する? まずエージェント同士で相談。

よくあるやり方は、エージェント同士を隔離して互いに知らせないこと。gtree は、ほかのエージェントが何を変更しているかを伝えます。同じ worktree なら、編集前にひと声かけてどちらが先か決めます。別の worktree(同じリポジトリのもうひとつの作業フォルダ)が同じファイルを変更していれば、gtree が表示します。

同じ worktree · まず相談左のエージェントが先に src/auth.ts を編集。右のエージェントは手を付ける前にそれを知らされ、左に伝言を残します。左が終わると右に自動で知らせが届き、右はその変更を踏まえて続きを編集します。Claude Code と Codex の間でも使えます。

聞くだけ:いま誰が変更している?

どのセッションでも「いま nimbus-sync を変更しているのは誰?」と聞けば、エージェントが自分で答えます。この Mac の Claude Code と Codex のセッションについて、どれが作業中か、何をしているか、どのファイルを変更したかがわかります。共有のコードを変更する前には、まず確認するよう gtree がエージェントに促します。

  • gtree で開いたセッションだけでなく、ほかのターミナルやエディタで開いたものも対象
  • ファイル単位まで:どのセッションが、どのファイルを、何分前に変更したか。未コミットの変更も含みます
  • 過去も覚えています。どのプロジェクトで何が聞かれ、どう結論が出たかを検索でき、作業前に「前に誰か試した?」を確認できます
  • 新しいセッションは、ほかで誰が作業中かを最初から知っています。あなたが伝える必要はありません

❯いま nimbus-sync を変更しているのは誰?

⏺gtree で確認:

  • rate-limitClaude Codeテスト実行中3 分前に src/limiter.ts を変更
  • retry-afterCodexあなた待ちsrc/headers.ts を変更、未コミット
  • main待機中未コミットの変更なし

⏺src/limiter.ts はいま別のセッションが変更中です。同じファイルを触るので、先にそのセッションに聞いてみます。

別の worktree · 表示する2 つの worktree がどちらもまだコミットしていないのに同じファイルを変更していると、サイドバーのその行に琥珀色の △ が出て、スタートページの「どれか見る」から比較できます。
個人版 · 無料 · 初期設定はオフ

チームメンバー:まだ push していないコードが見える

同僚とリポジトリを共有しているなら「チームメンバー」をオンに。自分たちの git リポジトリを通して、メンバーがまだ push していない変更が見えます。メンバーが変更中の箇所をあなたのエージェントが編集しようとすると、まず手を止めてあなたに確認します。

  • リポジトリごとにオンにし、双方がオンにすると見えるようになります
  • オンにすると、あなたの未コミットの変更が自分たちのチームのリポジトリに同期され(gtree のサーバーは経由しません)、アクセスできる人なら誰でも見られます。いつでもオフにできます
  • 「手を止めて確認」は今のところ Claude Code のみ対応です

02ネイティブで軽い

Electron ではなく、 24 MB のネイティブアプリ。

gtree は Rust で書かれ、画面は Zed エディターの UI フレームワーク GPUI で GPU に直接描画します。ブラウザも Node も同梱せず、開けばネイティブのウィンドウです。

  • git の読み取りは gitoxide(純 Rust)。コミットやプッシュは Mac 上の git が実行するので、SSH key や hooks はそのまま使えます
  • 長いリストは見えている行だけを描画し、重い git 処理はバックグラウンドで。画面が固まりません
  • 24MBダウンロード
  • 73MBインストール後
  • 約0.2秒クリックからウィンドウ表示まで
  • 約100MB待機中のメモリ
  • <1%待機中の CPU
  • ≈3%エージェント 3 つが作業中・1 つが待機中の CPU

Apple M4 · macOS 15 · gtree 0.3.14(CPU は 0.3.15)で計測。起動時間はウォームスタート 7 回の中央値(176 ミリ秒)、メモリは「アクティビティモニタ」の表示値、CPU は 1 コア換算の 20 秒平均です。

03やり直せる

壊れても大丈夫。 どのターンにも戻せます。

エージェントがターンを終えるたびに、gtree はそのターンで変更されたファイルを記録します。右側の「変更」→「AI の各ターン」でターンごとの diff を確認し、おかしなターンがあれば「このターンに復元」をクリック。

  • そのターンで触ったファイルだけを、ターン終了時の状態に戻します。ほかのファイル、ブランチ、ステージングはそのまま
  • 2 回クリックで実行されるので、うっかり押しても大丈夫。各ターンは 30 日間復元できます
  • 新しいセッションは、前回どこまで進んだかを最初から知っています
04ターミナルに張り付かない

ほかの作業へどうぞ。 必要なときだけ、gtree がお知らせします。

ターミナルを 4 つ切り替えてやっと気づいた。あのエージェント、許可待ちで 20 分止まっていた。

見張りは gtree が引き受けます。エージェントが許可や返答を求めると、macOS の通知でお知らせ。全プロジェクトのあなた待ちは「対応待ち」のいちばん上に並び、クリックすればそのセッションに入れます。

  • 知らせるのは必要なときだけ:許可、質問への返答。Claude Code が答え終わったのに返信していないときも知らせます
  • そのセッションを見ている間は通知しません
  • 通知をクリックすればその worktree へ。gtree が起動していれば、ウィンドウを閉じていても届きます

状態がひと目でわかる

  • 1Dock のバッジあなた待ちの件数(全プロジェクトの合計)
  • 回転この worktree のエージェントが作業中
  • ベルあなた待ち:許可や返信
  • △別の worktree もこのファイルを変更中
05プロジェクトをまたいで

フロントのエージェントが、 バックエンドのエージェントに直接聞ける。

「対応待ち」で「プロジェクトの関係図」を開くと、各プロジェクトで誰が作業中か、どのプロジェクトがどれに依存しているか、どの 2 つのエージェントがやり取り中かが 1 枚の図に。別プロジェクトの API がわからなければ、エージェントが向こうのエージェントに直接聞けます。

  • 答えるのは相手のセッションのコピーで、バックグラウンドで回答します。相手の作業は止まりません
  • Cargo、npm、Go で互いを参照しているプロジェクトは自動で認識。API 呼び出しのようにコードから読み取れない関係は、手動でも追加できます
  • 質問を受けられるのは、今のところ Claude Code のセッションだけです

安心して使える理由

  • gtree はコードをアップロードしません

    gtree はあなたの Mac 上でだけリポジトリを読み書きします。アカウント登録は不要で、gtree がコードをアップロードすることはありません。

  • リポジトリの変更は、あなた自身の git で

    コミット、プッシュ、リベースは Mac 上の git が実行します。認証情報、SSH key、hooks はそのまま使え、設定し直す必要はありません。

  • ブラウザエンジンを含まないネイティブアプリ

    Rust で書かれ、GPU で描画。ブラウザも Node も同梱していません。ダウンロードは 24 MB、約 0.2 秒(ウォームスタート)でウィンドウが開き、待機中のメモリは約 100 MB です。

  • 匿名の利用統計はオフにできます

    集計するのは利用者数と使用バージョンだけで、個人は特定できません。初回起動時にお知らせし、設定からいつでもオフにできます。
