# 撤销 Claude Code 的改动:回到任意一轮,关掉的会话也行

> AI agent 三轮之前把东西改坏了?对比三种撤销办法:git、Claude Code 的 /rewind,以及 gtree 的「AI 每一轮」—— 任意一轮的文件都能恢复,新会话还记得上次做到哪。

Published: 2026-10-22 · DobbyLab · https://gtree.dobbylab.com/zh/blog/undo-claude-code-changes/

想撤销 Claude Code 做的改动,有三种办法。**git** 能丢掉未提交的改动(`git restore <文件>`),但最远只能退到上一次提交。**Claude Code 自带的回退**(`/rewind`)能把代码退回对话里的某个时间点,但只管它用文件编辑工具做的改动。**gtree** 在 agent 每答完一轮时给 worktree 存一个检查点:任意一轮改了什么都看得到,点两下就能把那些文件放回去,不管这一轮来自哪个会话,上周关掉的也行。新会话一开头还知道上次做到了哪。

## 为什么撤销 AI 的改动比撤销自己的难?

自己写代码时,提交大致跟着思路走。AI 不是这样:二十分钟里 agent 可能答了八轮、动了十五个文件、跑了十几条命令,全都夹在你的两次提交之间。然后第六轮把测试改挂了:你想把第六轮的改动撤掉,前五轮的留着。

单靠 git 表达不了这件事:在它看来,上次提交到现在什么都没发生过。

## 怎么用 git 撤销 Claude Code 的改动?

如果 AI 开工以后你还没提交过,git 是最快的「全部不要了」:

```bash
git status                     # 改了哪些
git diff                       # 怎么改的

git restore src/auth.ts        # 丢掉一个已跟踪文件的改动
git restore .                  # 丢掉所有已跟踪文件的改动

git clean -n                   # 先预览会删掉哪些未跟踪文件
git clean -fd                  # 真删(小心,删了就回不来)
```

想在把任务交给 AI 之前留条后路,先存一份:

```bash
git stash push -u -m "交给 AI 之前"   # 把手上的改动(含新文件)先收起来
git stash apply                        # 之后取回来,stash 还留着
```

或者每次发提示词之前都提交一次。能用,但提交历史会塞满「wip」,之后还得 squash;而且总有一次会忘,偏偏就是出事那次。

## Claude Code 的 /rewind 怎么用?

Claude Code 在对话过程中会自己存检查点。输入 `/rewind`(或者在输入框为空时连按两次 Esc),选一条更早的消息,就能把对话、代码或两者一起恢复到那个时间点。「刚才两轮方向错了」这种情况,它是最快的。

检查点随对话一起保存,用 `claude --resume` 回到以前的对话后照样能 `/rewind`。每个会话保留最近 100 个检查点,默认大约 30 天后清理。

按 Claude Code 文档的说法,它有几类改动是不记录的:

- **shell 命令改的文件**:`rm`、`mv`、`cp`、一行 `sed`、格式化工具、代码生成器;
- **子 agent 做的编辑**(通常不记录);
- **会话之外的改动**:你手动改的、同时开着的其他会话改的。

它的定位是快速的本地撤销,不是用来代替版本管理的。

## gtree 怎么按轮回滚

[gtree](https://gtree.dobbylab.com/zh/) 换了个思路:不追踪一次次编辑,而是给结果拍快照。Claude Code 和 Codex 都支持。

### 每答完一轮,存一个检查点

连上 Claude Code(或 Codex)之后,agent 每答完一轮,gtree 都把 worktree 当时的状态存成一个**检查点**。存的是文件本身而不是编辑操作,所以 shell 命令改的文件、新建的文件也都在里面。被 git 忽略的、或者超过 1 MB 的新文件不存。

检查点是仓库里普通的 git 对象,挂在单独的引用下面,不在任何分支上;存检查点不会碰你的分支、暂存区和文件。保留 30 天。

### 每一轮改了什么:「改动 › AI 每一轮」

打开右面板的**「改动」**(⌃⇧G)。上半部分是未提交的文件,下半部分是**「AI 每一轮」**:当前 worktree 里的每一轮。每轮占两行:你的提问和时间,然后是改了几个文件、改了哪些,比如「3 个文件 · session.ts 等」。默认只列改过文件的轮次,因为大部分轮次只是一问一答;「⋯」菜单里可以把其他的也显示出来。

点一轮,它的详情在中间打开:

- 你的提问和 agent 最后的回复(先显示 4 行,点「展开全部」看完);
- 下面紧接着是这一轮具体改了什么的 diff。

跨会话也有效。昨天关掉的对话,它的每一轮还在列表里,「昨晚 AI 到底改了什么」有答案。

### 「恢复到这一轮」做了什么

选中一轮,点**「恢复到这一轮」**。按钮会变红、变成**「再点一次确认恢复」**,手滑点一下不会覆盖任何东西。

![点过一次之后,按钮变红,写着「再点一次确认恢复」,下面一行说明:会把这一轮动过的 2 个文件改回它结束时的样子;别的文件、暂存区和分支不动](/media/app/ai-turn-restore-confirm-zh-light.webp "第一次点只是确认,第二次才真的恢复")

第二次点下去,**这一轮改过的文件**会被写回它结束时的样子;其中当时还不存在的文件会被删掉。完成后会提示,比如「已把这一轮的 2 个文件恢复到它结束时的样子」。

它只动这一轮改过的文件,不会把整个工作目录退回那个时刻,也不碰你的分支和暂存区。

### 怎么撤掉出问题的那一轮

还是上面的例子,第六轮把测试改挂了:

1. **先选中第六轮**,看它改了哪些文件。这就是要退回去的清单。
2. **往前找最近一个也改过这些文件的轮次**(比如第四轮),选中它,点两次「恢复到这一轮」。这些文件就回到第四轮结束时的样子,也就是第六轮动手之前。
3. **看一眼第四轮还改了哪些别的文件。** 恢复会把第四轮动过的文件全都写回去;如果其中某个文件第五轮又改过,第五轮的改动也会跟着退掉。先看清楚再点。
4. **第六轮之前没有哪一轮改过的文件**,先用 `git diff <文件>` 看一眼;如果里面只有第六轮的改动,再用 `git restore <文件>` 退回。第六轮新建的文件直接删掉。

其他东西一概不动:别的文件、暂存区、分支、提交。恢复本身就是工作区里一次普通的改动,可以在上面的未提交改动里检查,也可以直接提交。

### 在提交图上看 AI 的每一轮

在**「提交历史」**(⌘3)里,工具条上的**「AI 每一轮」**开关会把最近三天的检查点画成从当前提交长出来的额外提交,标题是那一轮的提问。点一个就能看它改了什么,和普通提交一样。

![「提交历史」打开「AI 每一轮」开关后:最上面三行是 AI 检查点,下面是其他分支的泳道](/media/app/history-graph-ai-turns-zh-light.webp "打开「AI 每一轮」,agent 的检查点和你的提交画在同一张图上")

### 找到改动背后的那段对话

有时候撤销之前得先知道*为什么*这么改。在 AI 页按 **⌘Y**,顶上落下一个「历史对话」小窗,列着这个仓库所有 worktree 里以前的每段对话,按今天、昨天、近 7 天、更早分组。打字就能全部搜一遍。Claude Code 的对话按 **↩** 在它的 worktree 里接着聊;**⌘↩** 打开只读回放,命中的地方高亮,想接着聊时「继续这个会话」就在旁边。(Codex 的每一轮同样会出现在「AI 每一轮」里、能恢复;从这里接着聊目前只支持 Claude Code 的会话。)

![AI 页上的 ⌘Y 历史对话小窗:「搜索历史对话…」,以前的会话按今天、昨天、近 7 天分组,底部提示「↩ 继续 · ⌘↩ 只看」](/media/app/history-modal-zh-light.webp "⌘Y:这个仓库里以前的每段对话,一个快捷键就到")

### 新会话怎么知道上次做到哪?

撤销回答的是「放回去」,另一半问题是「上次做到哪了」。在一个 worktree 里开新会话时,agent 会自动收到这里上一个会话的简短总结:什么时候结束的、最近问了什么、最后说了什么、动过哪些文件。所以它能接着上次停下的地方做,而不是从头摸索,也知道哪些已经试过了。

agent 还能自己往更早翻。gtree 的 `recall` 工具能在你所有项目里搜最近 30 天每一轮的提问和结论,「上周 token 刷新是怎么修的?」这种问题,agent 自己就能找到答案。

## git、/rewind、gtree 该用哪个?

| | git | Claude Code `/rewind` | gtree |
|---|---|---|---|
| 撤销的单位 | 提交 / 整个文件 | 对话里的一条消息 | 答完的一轮 |
| shell 命令改的文件 | 能(未提交的) | 不记录 | 能 |
| 以前的会话 | 提交过才行 | resume 回那段对话后可以(约 30 天) | 所有会话,30 天内,不用找回对话 |
| 新会话知道上次做了什么 | 不知道 | 不知道 | 知道 |
| 看每一步改了什么 | 只能看提交之间 | 在对话里看 | 每一轮都有 diff |
| 会动分支 / 暂存区吗 | `reset`、`stash` 会 | 不会 | 不会 |

三者可以配合着用:对话进行中「不对,别这么改」用 `/rewind`;改动来自 shell 命令、或者过了一阵才发现、记不清是哪个会话干的,用 gtree;已经提交的,交给 git。

## 让撤销更容易的几个习惯

1. **任务做通了再提交**,不必每轮都提交。有了每轮的检查点,不需要拿「wip」提交当安全网。
2. **一个任务一个 worktree。** 回滚这个任务的轮次,碰不到别的任务的文件。参见[用 git worktree 同时跑多个 Claude Code](/zh/blog/run-multiple-claude-code-git-worktree/)。
3. **恢复前先看 diff。** 这一轮的 diff 就是恢复时会被改写的文件清单。
4. **别让两个会话稀里糊涂地共用一个目录。** 回滚一个会话的轮次,可能会动到另一个的活。参见[两个 AI agent 改同一个文件](/zh/blog/ai-agents-editing-same-file/)。

## 常见问题

### 会话关掉以后,还能撤销 Claude Code 的改动吗?

可以。Claude Code 本身:用 `claude --resume` 回到那段对话再 `/rewind`,但只能退回文件编辑工具做的改动。gtree:30 天内的每一轮都留在「AI 每一轮」里,不管来自哪个会话,shell 命令改的文件也在。git:只有改动还没提交、或者改之前你提交过,才退得回去。

### 恢复以后,出问题那一轮改的某个文件没变回来,为什么?

恢复只写回**那一轮**改过的文件。为了撤销第 5 轮而恢复到第 4 轮,写回的是第 4 轮动过的文件;第 5 轮改了、第 4 轮没碰过的文件保持原样。打开第 5 轮看它改了哪些文件,再用 git 恢复,或者从更早一个改过它们的轮次恢复。

### 恢复会改我的提交或分支吗?

不会。它只改写工作区里的文件,提交、分支、暂存区都不动;要不要提交由你决定。

### Codex 也能这样吗?

能。Codex 会话每答完一轮同样会存检查点,它的每一轮也会出现在「AI 每一轮」里,能同样恢复。从 ⌘Y 接着聊以前的对话,目前只支持 Claude Code 的会话。

### 新会话会知道上一个会话做了什么吗?

用 gtree 的话会。在一个 worktree 里开新会话,它会自动收到这里上一个会话的总结(最近的提问、最后的回复、动过的文件);更早的,agent 可以用 `recall` 工具去搜。

### 检查点里会包含我自己改的东西吗?

会。检查点存的是一轮结束时整个工作目录的样子,所以上一轮之后你手动改的内容也在里面。

gtree 本地功能免费、不用注册;gtree 不上传你的代码。[下载 gtree](https://gtree.dobbylab.com/zh/),连上 Claude Code 或 Codex,下次哪一轮改坏了,你能看清它改了什么,把那些文件退回去。
