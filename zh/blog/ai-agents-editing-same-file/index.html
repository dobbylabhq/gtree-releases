两个 AI agent 改同一个文件:怎么让它们先商量、不互相覆盖

2026年10月19日 · DobbyLab · claude-codecodexgit-worktreemerge-conflictsparallel-agents

要让两个 AI agent 不互相覆盖:要么给每个一个 git worktree、在合并前发现改到同一个文件;要么在它们共用一个目录时,让每个动手前都知道对方在做什么。会出什么事,取决于它们在哪儿干活。在不同的 git worktree 里,谁也覆盖不了谁,但合并时会冲突,办法是尽早发现重叠。在同一个目录里,一个 agent 可能直接改掉另一个改到一半的活,所以动手前每个都得知道对方在做什么。这两种情况都可以用 git 手动查;gtree 则一直在查,而且在同一个目录里更进一步:让两个 agent 知道对方的存在,能互相留话、商量谁先改。

两个 agent 碰到同一个文件,实际会发生什么?#

分两种情况,应对方法不一样。

不同 worktree。 每个 agent 有自己的工作目录和分支,互相看不到对方的改动。两边都改了 src/auth.ts,各自测试都通过,直到合并第二条分支时冲突才冒出来。如果两边改的是同一个函数,你就得手动解,而且往往已经想不起来两边当初为什么这么改。

同一个目录。 两个会话共用一个工作目录,没有任何隔离。最粗暴的那种事故 Claude Code 自己已经防住了:文件在它上次读取之后变过,它会拒绝这次修改,不会悄悄把旧内容写回去。真正的风险更隐蔽:agent B 重新读了文件,看到 agent A 刚写的内容,然后直接在上面改,却不知道那是 A 正在做的活。还有一种:A 改到一半,B 的编译就跟着挂,反过来也一样。

多开 AI agent 怎么避免冲突?#

不管用什么工具,这几个习惯都管用:

  1. 按功能区域分活,别按步骤分。 「搜索界面」和「登录限流」很少撞;「重构 auth」和「加 OAuth」几乎一定撞。
  2. 说清谁负责什么。 在提示词里写明这个 agent 负责哪些文件、哪些目录不要碰。
  3. 每个 agent 一个 worktree。 把悄无声息的覆盖变成看得见的合并冲突,后者好处理得多。
  4. 小步、勤合并。 只活一小时的分支很少冲突,活一周的基本都会。

用 git 检查有没有改到同一个文件#

各 worktree 里还没提交的改动。 下面这段会列出在不止一个 worktree 里都有未提交改动的文件(简单示意,假设路径里没有空格):

git worktree list --porcelain | awk '/^worktree /{print $2}' |
while read -r wt; do
  git -C "$wt" status --porcelain | awk -v wt="$wt" '{print $NF, wt}'
done | sort | awk '
  { n[$1]++; w[$1] = w[$1] " " $2 }
  END { for (f in n) if (n[f] > 1) print f ":" w[f] }'

两条分支已经提交的改动。 分别列出每条分支从 main 分出去以后改了哪些文件,再对比:

git diff --name-only main...fix-login
git diff --name-only main...search-box

到底会不会冲突? Git 2.38 及以上可以用 merge-tree 在内存里试合并,不碰你的工作目录:

git merge-tree --write-tree fix-login search-box

能干净合并时退出码是 0;有冲突时退出码是 1,并列出冲突的文件。

这些命令都好用,但得记得去跑。而没提交的那种情况,恰恰是 agent 干活时每分钟都在变的。同一个目录里的两个 agent,这些命令更是一点帮不上。

同一个目录里的两个 agent,怎么商量谁先改?#

这是 git 完全看不见的情况,也是 gtree 管得最细的地方。连上 Claude Code 或 Codex 之后,gtree 会记下哪个会话改了哪个文件。同一个目录里的两个 agent 要改同一个文件时,过程是这样的:

  1. agent A 改了 src/auth.ts。 gtree 把这次修改记在 A 的会话名下。用 sed、Python 脚本这类 shell 命令改的也认得出来,不只是 agent 自带的改文件工具。
  2. agent B 也要改这个文件。 在改动落下之前,gtree 往 B 的上下文里加一段提醒:src/auth.ts 几分钟前被另一个还开着的会话改过(gtree 往回看 30 分钟),那个会话在做什么;你们共用这个目录,没有 git 隔离,先重新读一遍文件。如果要改的是同一处,用 gtree 的 tell 工具跟对方商量谁先改、谁等对方做完。
  3. A 也会知道。 文件被别人动过的那一方也会收到提醒:有人改了你也在改的文件,里面不是你写的部分是它的,别当成意外改回去。
  4. 两边商量。 B 调用 tell 给 A 留话(「login() 我也要改,你那边改完了吗?」)。A 下次改文件、跑完一条 shell 命令,或者你下次跟它说话时就会看到。如果 A 正要结束这一轮、还有没看的留言,会先被拦下来看完再停。A 用同样的方式回话。
  5. 先改的那个做完会说一声。 一轮结束时,gtree 会自动告诉和它互相留过话的会话:这一轮做完了,改了哪些文件。等着的那个在下一步、或者你下次跟它说话时看到,就可以接着做。
  6. 编译挂了不会怪错人。 B 的编译或测试报错落在另一个还开着的会话刚改过的文件上时,B 会收到提示:这多半不是你的问题,别去动它的文件,用 tell 告诉它,先做不依赖编译通过的部分。

这些都发生在 agent 的对话里。gtree 不弹窗、不让你当裁判,也不拦任何修改:这些是 agent 读到之后自己照着做的提醒。Claude Code 和 Codex 之间同样适用,同一个 worktree 里一个 Codex 会话和一个 Claude Code 会话,也是这样互相打招呼。

想看它们聊了什么,打开「待处理」(⌘1):一个 agent 给另一个留的话,在接收方正在干活或在等你时,挂在它那一行下面,对方还没看到时标着「还没送到」;接收方闲着、留言 10 分钟还没送到的,会单独成一行出现在「也许要留意」里。

怎么知道两个 worktree 改了同一个文件?#

不同 worktree 之间不会互相覆盖,这里要做的是在合并之前就知道。gtree 盯着每个 worktree 的文件,磁盘上有变化后大约一秒半就刷新。两个 worktree 改了同一个文件,会在三个地方看到:

  • 侧栏。 那条线上没有会话状态图标时(开着的会话的状态图标会占掉这个位置),行尾出现琥珀色 △,悬停能看到有几个文件别处也在改。

  • 开始页。 点进这条线,开始页写着「N 个文件别处也在改」,点**「看是哪些」**列出文件和涉及的其他 worktree。

  • 「待处理」。 两边都还没提交的,出现在**「也许要留意」**里,按涉及哪几条线合成一行。

gtree 只标至少一边还没提交的重叠,因为那才是两个 agent 正在改同一个文件。两边都已经提交的,合并时 git 自然会告诉你,上面的 git merge-tree 能判断是不是真冲突。

情况 意思 在哪看到
两边都没提交 两个 agent 正在改这个文件 侧栏 △、开始页、「待处理」
一边已提交、一边还没提交 一边做完了,另一边还在改 侧栏 △、开始页

「待处理」里的每条重叠都有**「看对比」按钮,打开看改了什么。想收起一条,悬停后点「知道了」**,或者按 ⌫;同样的几个 worktree 又多改了文件、或者情况变了,它会再出现。AI 工具为自己的子任务临时建的 worktree 不算在内,免得添乱。

agent 能自己查谁在改这个文件吗?#

连上 Claude Code 或 Codex 之后,每个会话都能用 gtree 的工具,不用等别人告诉它:

  • who_touches 回答「还有谁在改这个文件」,范围是同一仓库的各个 worktree,以及依赖这个项目的下游项目;在当前目录里还会按会话分开列出。
  • who_is_working 列出其他 agent 现在在做什么。
  • tell 给另一个会话留话,就是上面那个。

新会话一开头还会收到一份简报:同一个目录和相关项目里还有谁在干活,以及有哪些现成的 worktree 可以直接复用(分支已合并、没有未提交改动、没有会话在用),不用再新建一个。这样它动手之前就能避开别人正忙的地方。

gtree 会锁文件、拦下修改吗?#

这些是提醒和标记,不是锁。gtree 会把重叠告诉你和 agent,但不会拦下修改、也不会暂停 agent;要不要等,由 agent 照着提醒自己决定。检测是按文件算的:两个 agent 改同一个文件里的不同函数,也会收到提醒,通常它们重新读一遍就接着干了。

常见问题#

两个 Claude Code 会话能在同一个目录里干活吗?#

能,但它们共用所有文件、没有隔离,随时可能撞上。真要并行干活,给每个会话一个 git worktree。如果确实要共用一个目录,gtree 会在一个 agent 要改另一个刚改过的文件前告诉它,并让它们能互相留话、商量谁先改。

Claude Code 自己能发现文件被别人改了吗?#

能发现一部分。文件在它上次读取之后变过,它会拒绝这次修改、要求重新读。但它不知道是谁改的、为什么改,这部分上下文是 gtree 补上的。

Codex 也能这样吗?#

能。Codex 会话在改另一个会话刚改过的文件前,一样会收到提醒,也能用 tell,做完同样会发「做完了」。同一个目录里的一个 Claude Code 会话和一个 Codex 会话,和两个 Claude Code 会话一样互相打招呼。

改到同一个文件就一定会冲突吗?#

不一定。同一个文件里改的是不同地方,git 会自动合并。重叠的意思是「合并前看一眼」;是不是真冲突,用 git merge-tree 一查便知。

在自己终端里开的 agent 也有用吗?#

有用。跨 worktree 的重叠标记来自 git,不需要别的。同一目录里的提醒来自 Claude Code 和 Codex 的 hook,连上之后任何终端里的会话都会上报。
